# 融策智能体整合与竞赛审查

审查日期：2026-10-29。对象为本目录中的整合版本；赛事条款来源为[深圳国际金融科技大赛官网](https://fintechathon.g-ican.com/)国内人工智能赛道的赛题说明和规则页面。此报告不是组委会认证，也不是获奖保证。

> **历史快照提示：** 以下正文、测试结果和“未接在线模型”描述记录的是本次接入前的审查状态，并非当前代码断言。后续模型接入和验证范围见 `QWEN_LIVE_INTEGRATION_2026-10-29.md`；历史测试不代表更新后的模型版本已通过相同测试。

## 结论

**智能量化不需要整体替换成一个新的项目。** 已交付的 S3 量化服务已经按银行理财场景调整为净值风险统计，接入 FinPilot 后可为产品对比提供有来源的历史波动、回撤和 CVaR。原 StockQuant 的股票筛选、证券收益回测和交易功能不应当成银行赛题核心功能展示。

当前作品已形成可运行的模拟系统，具有覆盖六场景的代码基础，但**尚不能认定符合大赛所有要求，也不能认定已经具备稳定获奖水平**。主要差距是缺真实在线模型、缺充分的六场景完整任务及真实模型安全评测、缺强隔离沙箱的运行证据，以及提交与资格条件尚未核实。

官网显示国内人工智能赛道作品提交日期为 **11 月 2 日**；具体截止时刻、报名和作品实际提交状态须队长在赛事系统核实。

## 1 已整合内容

1. FinPilot 离线包作为主工程，保留两个客户端、统一任务/授权/账本内核、六场景代码、模拟银行和商户、评测及资料。
2. S3 风险服务独立运行并实际调用 StockQuant 统计内核；FinPilot 传入合成理财净值，通过 HTTP 取得报告并验证请求号、产品集合、净值哈希、方法版本和单位。
3. 银行和商户 HTTP 适配器可注册。HTTP 模拟提供方通过 Outbox 工作进程在请求事务提交后派发；外部结果不明时需按原编号核对，不能宣称成功。
4. 理财页面显示可解释的风险统计和数据来源；缺历史、非净值、明显非日频/缺口或服务失效时显示 NA。银行侧适当性、条款和预算规则仍为权威。
5. 订阅查询改为确认前不返回详情，确认后经授权内核查询。理财比较保留用户预算，卡片查询不会默认变成申请。
6. 修复两个客户端在 `/app/`、`/im/` 下的静态资源路径。统一启动器以模拟模式、独立服务和回环地址运行，不自动修改数据库。

六个固定示例的最后一次 HTTP 结果：转账等待授权，账单查询成功，理财比较成功，卡片查询成功，订阅查询等待授权，生日采购等待澄清。等待授权或澄清是中间状态，**不是该场景已完成**。这不是独立盲测，也不是比赛完成率。

30 条开发集诊断由判定器得到：可执行任务完成 **2/6**（另 2 条部分完成、2 条未知）；澄清正确 **3/6**；应拒绝任务拒绝 **2/6**；12 条攻击均判为拒绝，禁止效果计数为 0。每条结果的 `review_status` 均为 `pending_review`。这些是小样本、单次、模拟规则运行的初步信号，且判定器本身也需复核；不能将其外推为正式完成率或安全保证。尤其可执行、澄清与应拒绝任务的结果显示系统距离比赛要求还有明显工作。

代码运行模式为 `mock`。模型相关的真实理解、工具选择、规划能力、模型注入防御、延迟和成本，目前均无实测结果。不能把已有规则测试、静态文件或旧团队报告写成在线模型表现。

## 4 最重要的剩余问题

### P0：在线 AI 能力缺失

当前实现的 `APP_MODE=mock` 使用规则编译器；`live` 与 `offline_replay` 没有可运行的实现，入口已失败关闭。比赛考察自然语言理解和任务规划，因此这是竞争力和赛题完成度的核心缺口。应接入真实模型，限制其只生成结构化候选；对目标、金额、对象、数据来源、权限和工具在服务端独立校验；敏感操作仍由人工确认和内核授权。模型供应商、版本、提示词版本、脱敏与数据使用条款要留痕。

### P0：安全隔离未达到可证明的强隔离

Windows 运行时通过 AST、子进程和 Python audit hook 做限制，但 CPU、内存、进程数等硬限额及内核文件系统隔离未生效；容器策略尚未实测。需在适用环境落实资源限制、无网络/受限文件系统、权限与系统调用隔离，证明不可用即关闭，并进行越权与注入测试。

### P0：端到端任务效果与评测不足

各场景模块测试和六条冒烟请求不足以推断任务完成率。需冻结数据和判定口径，按任务类型分别统计可执行任务、澄清、拒绝与攻击；对未见表达、异常路径、跨场景及并发多次执行，人工复核失败例。历史报告对一批禁止效果存在判定口径误报说明，见原 `finpilot/docs/eval-oracle-diagnosis.md`；不能把未复核的数字当作比赛成绩或实际资金损失。

### P1：材料、许可证与行政条件

旧 DOCX/PPT、README、OpenAPI 和来源清单来自旧快照，必须按当前实现重新核对。StockQuant 备份包含 MIT 许可证并已随源码保留，仍需确认贡献者权属、其他依赖及 AI 使用披露。全员在校资格、同队限制、报名、提交回执、模拟渠道及 TOTP 验证方式是否获认可，需要队长核实；官方文件对视频/安全自评存在口径差异，建议按较严格要求准备并取得确认。

## 5 面向四人的后续分工

- **A：产品与交互。** 六场景可操作界面、用户澄清、错误/未知状态展示、两客户端浏览器验收和真实用户试用。
- **B：可信执行。** HTTP 银行/商户端到端、回调/重试/对账、余额守恒、并发、崩溃恢复和强隔离环境。
- **C：理财与数据。** 风评/条款/申赎链路、量化口径和 NA 边界、可追溯数据、许可证和第三方材料。
- **D：模型与评测。** 在线模型结构化候选及服务端校验、提示注入/越权、基线消融、留出集和评测结果复核。

合并时统一契约与身份授权，由其他成员复审关键模块；每个“通过”都保留代码版本、数据/配置、执行命令、预期与实际结果。最终先做完整验收，再决定对外宣传范围。
