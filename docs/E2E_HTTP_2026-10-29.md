# 六场景真实 HTTP 验收（2026-10-29）

本文记录用**真实 HTTP**（不是 FastAPI TestClient）对运行中的演示栈做六场景验收的结果。所有请求只使用合成数据与模拟资金。脚本：`scripts/e2e_http_smoke.py`；证据：`evidence/e2e_http_20261029T085930Z.json`、`evidence/e2e_http_workerfix_20261029.json`。

## 1. 方法

- 登录 `user_demo_01`，所有业务请求带 Bearer token；跨用户用例另用 `user_demo_02`。
- 每场景覆盖 5 类：正常、缺信息、否定/条件、重复提交、跨用户越权；另加场景特有补充（共 35 条）。
- 断言口径：**前后差值/相对关系**，不写死会随演示库漂移的绝对值；资金类用例必须有 operation 与回执/提供方引用，只读用例以 `domain_result` 为可核验结果。
- TOTP 用 `totp_at(DEMO_TOTP_SECRET, ...)` 现算；因服务端有 10 分钟同计数器防重放，脚本会等到下一个口令窗口再取码。

## 3. 归因

### 3.1 已定位并修复：Worker 进程没有注册提供方适配器（P0，跨场景）

- 现象：`run_demo.py` 给子进程设 `PROVIDER_MODE=http`，但 `worker_outbox.py` 只在 API 进程里注册适配器；Worker 投递时 `get_adapter` 抛 `PROVIDER_CAPABILITY_MISSING(adapter_not_registered)`。操作直接 `failed`，任务却停在 `reconciling`（终态不一致），`.runtime/worker_outbox.py.log` 全是 `delivered=0 retried=N`。
- 影响：所有**异步**外部效果（转账受理、商户预订）都走不通；同步路径不受影响，所以之前只跑同步测试时看不出来。
- 修复：
  1. 把注册逻辑抽到 `finpilot/adapters/registry.py`，`app.register_adapters()` 改为薄封装；
  2. `scripts/worker_outbox.py`、`scripts/worker_scheduler.py` 启动时调用 `bootstrap()` 注册并打印 `提供方适配器已注册：[...]`；
  3. 新增 `tests/integration/test_worker_bootstrap.py`：一个用例验证注册表能注册出「稳定业务键 + 查询」能力齐全的适配器，另一个用子进程实跑 `worker_outbox.py --once` 断言启动日志里出现四个适配器。
- 复验：重启演示栈后重跑 S1/S6，S6 的错误码从 `PROVIDER_CAPABILITY_MISSING` 变成 `PARAM_INVALID`——说明适配器通路已通，剩下的是**参数契约**问题（见 3.2）。

### 3.3 脚本自身问题（已修，不计入产品缺陷）

- TOTP 同 30 秒计数器复用被防重放拒绝 → 等下一个口令窗口再取码，最多重试 3 次；
- 重复提交断言从"硬编码条数"改为"与提交前计数比较"；
- 只读场景 `domain_result` 的 wrapped/flat 两种形态兼容；
- 否定类用例按规格断言"无资金类 operation + 余额零变化"，不要求零 operation（澄清/阻断也可能产生只读步骤）。

### 3.4 演示库状态导致的差异（未放宽断言）

- `account_salary` 可用额度被历史失败任务消耗，S1 改用储蓄卡；
- 9 月无流水，S2 上月报表为空账期，只校验账期/截止时间/空账期标注。

## 4. 修复后的复跑（S1、S6）

`evidence/e2e_http_workerfix_20261029.json`：11 条 **PASS 8 / FAIL 3**（S1-normal、S1-negation、S6-normal）。

- S6-normal 错误码由 `PROVIDER_CAPABILITY_MISSING` → `PARAM_INVALID`：适配器注册修复生效，剩下的是 `merchant.book` 请求参数契约（金额/商品/商户/时间字段）与沙箱校验不一致。
- S1-normal 仍停在 `pending`/`reconciling`，属 D8（异步受理与回调对账）。

## 5. 结论与下一步

真实 HTTP 验收把"六场景已完成"的说法推翻了一半：**查询类与澄清/阻断类多数可用，资金与外部效果的异步通路存在系统性问题**，且 S3 的测评与申购完全不可用。本次已修掉最关键的 Worker 适配器缺陷并加了回归测试；其余按优先级：

1. D1/D2 风险测评：补问卷 HTTP 入口（或澄清收集答案）+ 失败步骤收敛；
2. D8 异步受理→回调→对账闭环，确保任务终态可达；
3. D3 产品解析、D4 意图优先级、D5 歧义澄清、D6 否定/越权语义；
4. D7 预留额度释放与失败恢复。

在这些修完并用同一脚本复跑通过之前，不能把对应场景写成"已验收"。
