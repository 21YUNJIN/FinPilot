# 千问模型接入记录（2026-10-29）

在线模式使用 OpenAI 兼容的 chat completions 接口，输出严格受限于场景、动作、原文片段和不确定标记。模型不接触执行工具，也不能提供金额、收款人、账户或授权；这些信息及执行条件由原系统负责核对。写操作还要求原文出现独立识别的动作证据，歧义、冲突、否定和部分条件语句进入澄清。上述规则无法识别所有表达及攻击，因此必须继续安全评测，不能作为生产保障。

发送前会过滤部分敏感信息和已知注入模式；脱敏并不完整，只可输入合成数据。使用本模式时输入会发往配置的外部模型服务，可能产生费用；上线前应审核数据授权、服务条款及隐私处理。API 返回错误、超时或结构无效时停止处理，不自动降级为 mock。`offline_replay` 和真实模型自动评测仍未实现。

之前对模型服务使用合成文本做过独立调用，HTTP 200；这不构成项目内端到端测试。本轮在隔离 PostgreSQL 中用 HTTP 模拟模型服务完成 29 项定向测试，覆盖六场景编译路由、缺金额、同名联系人、错误输出、部分脱敏及转账确认前余额不变。测试并不证明六场景闭环、真实模型准确率、全部隐私或安全要求达标。真实模型集成运行需要用户撤销已暴露密钥并在本机配置新密钥，操作见根目录 README。

接入后的一次后端全量回归为 671 项通过、1 项依赖弃用警告；运行启动后新增了旧计划失效保护，所以不能将该全量结果描述为保护修改后的完整回归。修改后的模型、API 确认、跨场景、HTTP 修复与量化集成定向测试共 65 项通过，1 项依赖弃用警告；包括待确认任务改意后旧计划不能再确认。原始结果见 `evidence/` 下带时间戳的测试日志。

旧的整合审查、原项目报告、规则模式评测和前端测试都是历史版本证据。最终参赛前仍需逐项核对官方要求，执行真实模型六场景任务及安全评测、异常恢复、资源隔离和材料复核；获奖无法保证。
